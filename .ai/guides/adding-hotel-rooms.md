# Guide: Adding Hilbert's Hotel Rooms

This guide explains how to add a new room to the check-in terminal's selection
list. The result is a `hilbertHotelRoom` prototype that maps players into a
runtime-loaded map when they create a room with that archetype.

## TL;DR checklist

1. Map a room in a debug client and give it a `HilbertHotelLandingMarker` where
   guests should arrive.
2. Fill the room's grid atmosphere (`fixgridatmos <gridUid>`) so guests can
   breathe.
3. Save it as a **map** with `savemap` under
   `Resources/Maps/_PS/HilbertHotel/<name>.yml`.
4. Add a `hilbertHotelRoom` prototype to
   `Resources/Prototypes/_PS/HilbertHotel/rooms.yml`.
5. Add a display-name LocId to `Resources/Locale/en-US/_PS/hilbert-hotel.ftl`.
6. Build, lint and (optionally) run `HilbertHotelTest`.

## 1. Map the room

Use the in-game mapping tools, e.g.:

```
mapping 0          # open a mapping session on map 0 (debug client)
loadmap /Maps/_PS/HilbertHotel/room_cozy.yml   # or start from a blank map
```

Recommended contents:

- **Walls all around** so guests cannot walk into space.
- A **`HilbertHotelLandingMarker`** (`HilbertHotelLandingMarker`, found under the
  "Hilbert Hotel" suffix in the entity spawn menu) on the tile where arriving
  guests should appear.
- A **`HilbertHotelExit`** door on a wall. If the map does not include one, the
  system spawns one at the landing point when the room is created.
- A **`HilbertHotelRoomController`** console. If missing, the system spawns one
  next to the landing point.
- Any furniture/props you want. Everything on the map is deleted with the room
  once it has been empty for 5 minutes, so don't put round-critical items in.

Do **not** rely on a `BecomesStation` component: runtime map loads do not create
stations, but keeping rooms station-free avoids confusing map tooling.

### Atmosphere is mandatory

Runtime-loaded maps start as vacuum unless the map file carries grid atmosphere
data. Before saving, run:

```
fixgridatmos <gridUid>
```

This gives every tile on the grid the standard roundstart mix. You can verify
with a gas analyzer or `showatmos` before saving.

`room_cozy.yml` was generated by `Tools/gen_hilbert_room.py`, which writes the
format 7 `GridAtmosphere` block by hand; it is a useful reference if you want to
generate rooms procedurally.

### Converting BYOND/SPlurt `.dmm` rooms

`Tools/convert_dmm_room.py` converts a BYOND `.dmm` room map (for example the
SPLURT-tg condo maps in `modular_zubbers/code/modules/condos/_maps/`) into an
SS14 format 7 map:

```
python3 Tools/convert_dmm_room.py <input.dmm> Resources/Maps/_PS/HilbertHotel/<name>.yml --name "Room Name"
```

It maps tiles, walls, windows, doors, the hotel exit/controller and a curated
set of SS14-native props (beds, tables, chairs, closets, toilets, sinks,
mirrors, bookshelves, dressers, railings, fireplaces, carpets, water).
Unsupported props are skipped and printed as a report; no SPLURT sprites are
ported. The converted maps in this repo came from that tool. Always load the
result once and check the atmos soak test (`AllRoomArchetypesLoadAndHoldAir`),
because a single missing wall/exit seal depressurizes the whole room.

The converter also handles the things that make a runtime-loaded map playable:

- `Gravity: enabled: true, inherent: true` on the grid (the component defaults
  to disabled).
- `anchored: true` on every placed prop, so nothing is pushable.
- `needsPower: false` overrides for every prototype that inherits
  `ApcPowerReceiver` (resolved through prototype parents), because rooms have
  no APC. BYOND light fixtures are mapped to `AlwaysPoweredWallLight`, which
  needs no power at all.
- Furniture collisions: only one large furniture prop survives per tile
  (priority: bed > toilet/sink > window/door > table/bookshelf > chair >
  closet). Floor/wall decor and structural entities are never culled.
- The landing marker is placed on the nearest **entity-free** floor tile
  reachable from an exit, and a controller that would crowd the door is moved
  away. The SS14 controller is also non-blocking.

## 2. Save the map

```
savemap /Maps/_PS/HilbertHotel/<name>.yml
```

- Use **`savemap`**, not `savegrid`. The room loader expects a file containing a
  single `MapComponent`; grid files are rejected with
  `"Expected Map but got Grid"`.
- Keep the file under `Resources/Maps/_PS/HilbertHotel/`.
- Re-open the map with `loadmap` afterwards to confirm it loads cleanly.

## 3. Register the archetype

Append a prototype to `Resources/Prototypes/_PS/HilbertHotel/rooms.yml`:

```yaml
- type: hilbertHotelRoom
  id: MyHotelRoom              # unique prototype id
  name: hilbert-hotel-room-mine # LocId (see step 4)
  mapPath: /Maps/_PS/HilbertHotel/my_room.yml
  order: 10                    # lower = earlier in the selection list
  # landingOffset: 1,0         # optional, added to the resolved landing point
```

The terminal's selection list is built from every loaded `hilbertHotelRoom`
prototype, sorted by `order` then id. No C# changes are needed to add a room.

## 4. Localize the name

Add to `Resources/Locale/en-US/_PS/hilbert-hotel.ftl`:

```ftl
hilbert-hotel-room-mine = My Cozy Getaway
```

Missing keys are not fatal at prototype load, but the selection list will show
the raw key. `Content.YAMLLinter` does not validate LocId usage, so double-check.

## 5. Validate

```bash
dotnet build SpaceStation14.sln
dotnet build Content.YAMLLinter/Content.YAMLLinter.csproj
dotnet run --project Content.YAMLLinter -c Debug --no-build   # expect: No errors found
dotnet test Content.IntegrationTests/Content.IntegrationTests.csproj \
  --filter "FullyQualifiedName~HilbertHotelTest"
```

## Testing in game

1. Spawn a `HilbertHotelTeleporter` (admin spawn menu → "Hilbert Hotel" suffix,
   or `spawn HilbertHotelTeleporter`).
2. Interact with it, type a room code (e.g. `1337`) and pick the room style.
3. You are teleported into a fresh copy of the map.
4. Share the code: another player can check into `1337` from any terminal. If
   you lock the room from its `HilbertHotelRoomController`, only you (and
   trusted guests) may enter. Unchecking "List this room publicly" hides it from
   other players' terminals.
5. Use the `HilbertHotelExit` door to leave. The room stays loaded for 5
   minutes after the last guest leaves, then is deleted.
6. A player may only own one room at a time. The controller's "Delete room"
   button (or the Delete button next to your room in the terminal's listing)
   removes it and ejects everyone inside; you can then create a new one.

## Notes and gotchas

- Room maps are independent instances: two players in room `1` and room `2`
  with the same archetype get separate map copies.
- `landingOffset` is in world tiles and is applied after the marker/spawn
  point/grid-center fallback, so it can be used to nudge arrivals off a
  furniture tile.
- If a room map has no landing marker, the loader falls back to a latejoin
  spawn point, then any non-observer spawn point, then the first grid's center.
  The debug station map (`/Maps/Test/dev_map.yml`) is registered as
  `DebugStationHotelRoom` for testing this fallback.
- Room maps can be large, but every active room costs memory; the terminal's
  `MaxRooms` data field caps how many rooms that terminal may create (the limit
  is per terminal, not global). Creating rooms has a 5-second cooldown per
  terminal so delete/recreate cycles cannot spam map loads.
